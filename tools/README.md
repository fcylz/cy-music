# cy-music 曲库维护脚本

两个独立脚本，纯 Python 标准库，无第三方依赖（Python 3.8+）。

| 脚本 | 作用 | 会不会动文件 |
|---|---|---|
| `tools/match_lyrics.py` | 把 LRC 歌词和 MP3 自动对上号，统一改名 | 会（改名，可 `--dry-run` 预览） |
| `tools/update_playlist.py` | 扫描曲库，生成 `index.json` 与 `歌单.txt` | 只写这两个文件 |

---

## 一、文件名约定

```
songs/歌名-歌手.mp3
songs/歌名-歌手.lrc
```

- 分隔符是 **半角 `-`**，且歌名部分不含 `-`。
- 歌手名可以含 `-`（如 `A-Lin`），脚本按**第一个** `-` 拆分。
- 万一歌名确实含 `-`（如英文歌），脚本会用已有歌单里认得的歌手名兜底切分。

---

## 二、match_lyrics.py

### 解决什么问题

播放器只认「扩展名前逐字符相同」的歌词。从歌词站下载回来的文件常长这样：

```
songs/人间-王菲.mp3        ← 音频
songs/人间 - 王菲.lrc      ← 歌词，中间多了空格
```

旧逻辑直接判成"无歌词"，歌就哑了。本脚本把这类差异收敛掉。

### 配对四层，从强到弱

| 层 | 判定 | 处理 |
|---|---|---|
| L1 | 去扩展名后逐字符相同 | 已经配好，不动 |
| L2 | 规范化后相同（全半角、大小写、空格、`-`/`_`、中英文括号） | 自动改名 |
| L3 | 读 LRC 里的 `[ti:]`/`[ar:]`，或首行 `歌名 - 歌手`，与文件名交叉匹配 | 自动改名 |
| L4 | 歌名相似度 ≥ 0.85 且歌手一致 | **只报告，不改名** |
| — | 同一歌词命中多个音频 | 报歧义，不改名 |

模糊匹配一律不自动执行——改错名比不改更麻烦。

### 用法

```bash
python tools/match_lyrics.py                # 出报告 → 问你要不要改
python tools/match_lyrics.py --dry-run      # 只看报告，不动文件
python tools/match_lyrics.py --yes          # 不问，直接改
python tools/match_lyrics.py --collect      # 先把散落在别处的文件收进 songs/
python tools/match_lyrics.py --report 报告.txt
python tools/match_lyrics.py --fuzzy 0.9    # 收紧模糊阈值
```

### `--collect`：文件没放进 songs/ 时用它

网页上传很容易把文件扔在仓库根目录，而且命名常带空格：`歌名 - 歌手.mp3`。
`--collect` 会把它们收回来，并顺手把名字规范成 `歌名-歌手`：

```
不为谁而作的歌 - 林俊杰.mp3 + .lrc   ->   songs/不为谁而作的歌-林俊杰.mp3 + .lrc
```

- 只搬同目录内配得上对的音频和歌词（L1/L2/L3 才搬，L4 模糊匹配不搬）
- `songs/` 里已有同名 → 报冲突，不覆盖
- 没找到音频的孤零零歌词 → 留在原地，报告里列出来
- 默认从仓库根扫描，可用 `--from` 指定别的来源目录

不带 `--collect` 时脚本只处理 `songs/` 内部，不会去翻别的地方。

退出码：全部配好返回 `0`，存在弱配/歧义/冲突/孤立返回 `1`，方便接 CI 报警。

### 安全策略

- 只改**歌词**名，永远不动音频名；一律以音频文件名为准。
- 目标名已存在 → 跳过，不覆盖。
- 目标名含 Windows 非法字符（`\ / : * ? " < > |`）→ 跳过，不擅自清洗。
- 有改名动作时写 `配对日志.txt`，记录旧名 → 新名和配对依据。

## 三、update_playlist.py

### 一次扫描，两份产出

- `index.json` —— 播放器读的曲目索引（`name` / `mp3` / `lrc`）
- `歌单.txt` —— 给人看的排版歌单（按歌手分组、全局连续编号）

两者来自同一次扫描，不会像以前那样一个更新了另一个没更新。

### 歌单顺序是"继承"来的，不是算出来的

现有歌单的组序（陈奕迅 → 杨千嬅 → 林俊杰 → …）和组内顺序是人工调过的，
既不是拼音序也不是数量序。如果每次重新排序，git diff 会整篇重写。

所以脚本每次先读已有 `歌单.txt` 当**顺序锚点**，只做增量：

- 已有歌手的新歌 → 追加到该组末尾
- 新歌手攒够 2 首 → 从"其他歌手"升级为独立组，放在"其他歌手"之前
- 删除的歌 → 从歌单移除，其余顺序不动

`歌单.txt` 不存在时才退回默认规则（组按首现位置、组内按歌名）。

### 分组规则

- 歌手 **≥ 2 首** → 独立分组，行内只写歌名
- 歌手 **1 首** → 并入末尾「其他歌手」，行内写 `歌名 — 歌手`
- 组合歌手（`张靓颖&许嵩`）整体算一个歌手，不拆；显示时 `&` 两侧补空格

### 用法

```bash
python tools/update_playlist.py                 # 生成两份文件
python tools/update_playlist.py --check         # 只检查是否过期（过期退出码 1）
python tools/update_playlist.py --dry-run       # 不写盘
python tools/update_playlist.py --no-index      # 只更歌单
python tools/update_playlist.py --base-url https://xxx/songs
```

### 名称清洗：新歌名对不上时改这里

脚本顶部三个常量，遇到新的脏数据往里加就行：

```python
SINGER_ALIASES = {                # 歌手名归一
    "G.E.M.邓紫棋": "G.E.M. 邓紫棋",
}
TEXT_REPLACEMENTS = [             # 歌名/歌手名的全局替换
    ("蒋雪儿Snow.J", "蒋雪儿"),
]
UNKNOWN_SINGER = "佚名"           # 歌手名为纯下划线时显示这个
```

## 四、CI 怎么跑

`.github/workflows/build.yml`：push 到 `songs/` 后自动执行

1. `match_lyrics.py --dry-run` —— 只把配对情况打进日志，不阻断
2. `update_playlist.py` —— 生成 `index.json` 与 `歌单.txt`
3. 有变化就提交

**CI 里不做改名**。改名留给人执行——让 bot 改文件名风险太高。

## 五、常见问题

**问：我上传的新歌放到仓库根目录了，没进 songs/，怎么办？**
跑 `python tools/match_lyrics.py --collect`，它会收进 `songs/` 并统一命名，
然后跑 `python tools/update_playlist.py` 更新歌单。两条命令，不用手工搬。

**问：为什么我的新歌进了"其他歌手"？**
歌手不足 2 首。再放一首同一歌手的歌，下次运行会自动升级为独立分组。

**问：为什么歌单里某首歌的歌手显示"佚名"？**
文件名是 `歌名-____________` 这种，歌手名被抹掉了。要么改文件名，要么在
`SINGER_ALIASES` 里给这个下划线串加一条映射。

**问：新增的歌排到组里最后了，想插到中间怎么办？**
直接用编辑器把歌单里的行挪到想要的位置，下次运行脚本会以新顺序为准。

**问：Windows 上 `python` 命令找不到？**
用 `py tools/update_playlist.py`，或装个 Python 时勾选 "Add to PATH"。
